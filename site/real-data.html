Real data

We plugged in the trial key, and harvested the real thing

With our FortyGuard Temperature API® trial key, we first tested coverage: Cotonou is not in the mesh yet (0 tiles, verified Aug 27), Phoenix is. We then harvested three full days of real measurements in Phoenix, mid-heat-wave, and every harvested day re-anchors the model.

≈70 requests → 60 readings: one request per point-day (60) plus a handful of one-off coverage probes; every response is cached locally and never re-requested (credit-aware).

What is real, and what is simulated, stated plainly: the API delivers each point's real daily minimum, mean and maximum (the mesh's native granularity: full-day statistics per tile). The hourly shape between those bounds is simulated, and the demo accelerates time so the wave is visible in two minutes. The re-anchoring is a simple affine fit: the simulated daily curve is stretched to pass exactly through the real min and max. On the live deployment the backend calls the Temperature API® itself, every 24 h (live sync): each new real day is pulled the moment it closes and the feed is re-anchored automatically, so the numbers above grow on their own, no manual re-harvest. All of it is public: harvest.py (harvest), backend/data/livesync.py (live sync) and backend/data/real_data.py (re-anchoring).

Cotonou, when the mesh arrives

The Cotonou configuration is already calibrated, and waiting

🇧🇯 A Cotonou model calibrated on real weather

While mesh coverage is pending, the Cotonou simulator is anchored on real Open-Meteo observations (Aug 21–27: mean 26.6 °C, humidity ~83%, hourly bias −0.63 °C, reproducible with validate.py). The simulated heat wave matches a documented extreme (Cotonou record ~38 °C in the hot season); with humidity, feels-like crosses 40 °C.

🔄 One pipeline, zero code changes

When Cotonou enters the mesh: harvest.py --city cotonou collects the real days, train.py re-anchors the model in under 30 seconds, and the demo's real-data panel opens on Cotonou, with alerts in French + Fon. Same system, same API, a different city file.
